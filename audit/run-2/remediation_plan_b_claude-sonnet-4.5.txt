```rust
/// Check if an expression tree references a specific variable by name.
fn expr_references_var(&self, node: Node, source: &[u8], var_name: &str) -> bool {
```

### T6: Function global re-taint ★★ HIGH

**Verdict:** Document limitation + 1 test — defer fix to TODO.md  
**Finding:** 1/5 models (gpt-5.3-codex) — single model, high value

**Analysis:**
Current code (lines 411-420) snapshots taint state at function definition, walks body, restores state. If a global is clean at definition but becomes tainted before call, the function body isn't re-validated. This is a limitation of the intra-procedural model.

Example:
```bash
x="clean"
f() { echo "$x"; }  # validated with x=clean
x=$(getenv SECRET)   # x becomes tainted
f                    # body not re-validated
```

At SSA level, inlining uses the current (tainted) version of `x`, which is correct. But the *validator* doesn't emit a diagnostic because validation happened at definition time.

**Action:** Document limitation, add test showing current behavior, defer fix

**Test:** `neg_function_global_retaint_limitation`  
Input: (example above)  
Assert: **Currently compiles** — add `// TODO: DD#47 — inter-procedural taint tracking` comment  
Why: Documents known limitation of intra-procedural model

**Documentation:** Add to `docs/TODO.md`:
```markdown
## Taint Model Limitations

### Inter-procedural taint tracking (DD#47)
Function bodies are validated once at definition with taint state at
that moment. If a global becomes tainted between definition and call,
the body is not re-validated. At SSA level, inlining uses the current
(tainted) variable version, which is correct — but the validator
doesn't emit diagnostics for the tainted read.

Fix requires: call-site re-validation or inter-procedural analysis.
```
