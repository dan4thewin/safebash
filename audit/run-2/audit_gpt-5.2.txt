### 1) TAINT BYPASS: `$(getenv …)` / `$(argv …)` used *directly* is never SB4020’d  
**Script (passes today, uses taint):**
```bash
#!/bin/bash
echo "$(getenv UNTRUSTED)"
```
**Why not caught:** `check_expr_reads()` only flags `simple_expansion` (`$x`), `${…}`, and arithmetic expansions. It does **not** treat `command_substitution` as a tainted read at all, so taint sources used without an intermediate variable bypass SB4020.  
**Severity:** CRITICAL

### 2) TAINT BYPASS: redirection targets (and heredoc bodies) are not taint-checked  
**Script (tainted file write):**
```bash
#!/bin/bash
out="$(getenv OUT_PATH)"
echo PWNED > "$out"
```
**Script (tainted data sent via heredoc expansion, no cmdsub):**
```bash
#!/bin/bash
x="$(getenv UNTRUSTED)"
cat <<EOF
$x
EOF
```
**Why not caught:** `walk_statement()` descends into `"redirected_statement"` children using `walk_statement()`, but there is **no** `check_expr_reads()` pass over redirect nodes / heredoc bodies. The only heredoc-specific rule (`SB5002`) rejects `$(...)` in heredocs, but **not** `$x` expansions.  
**Severity:** CRITICAL

### 3) HERESTRING/HEREDOC FALSE CLEAN: `read`/`mapfile` targets become “clean” just because `<<<`/`<<` exists  
**Script (launders taint into a “clean” var):**
```bash
#!/bin/bash
x="$(getenv UNTRUSTED)"
read y <<< "$x"
echo "$y"
```
**Even worse (no variable needed):**
```bash
#!/bin/bash
read y <<< "$(getenv UNTRUSTED)"
echo "$y"
```
**Why not caught:** `handle_read()` sets `is_clean_source = has_herestring || has_heredoc` and never inspects whether the here-string/heredoc contains tainted expansions/command-subst. Also, `handle_command()` special-cases `read/readarray/mapfile` and does **not** run `check_expr_reads()` over their redirects at all.  
**Severity:** CRITICAL

### 4) TAINT BYPASS: taint does not propagate through arithmetic/array RHS in assignments (laundering)  
**Script (arithmetic laundering):**
```bash
#!/bin/bash
x="$(getenv NUM)"

```
**Script (array literal laundering → element read allowed):**
```bash
#!/bin/bash

```
**Why not caught:** assignment taint is computed by `expr_is_tainted()`, but it only considers `simple_expansion`, `${…}`, `command_substitution`, `string`, `concatenation`. It ignores arithmetic expansions and array literals, so the LHS becomes **Clean** and later reads evade SB4020.  
**Severity:** CRITICAL

### 5) BLESS VALIDATION GAP: bless can “validate” without referencing the variable (tautology bless)  
**Script:**
```bash
#!/bin/bash
x="$(getenv UNTRUSTED)"
bless x [[ -n 1 ]]   # always true; does not inspect $x
echo "$x"
```
**Why not caught:** `handle_bless()` does not require that the test expression depends on `$x` (or even mentions it). After the bless, `mark_blessed(x)` is unconditional. Runtime `Bless` then enforces only the tautology.  
**Severity:** HIGH (effectively a complete bless bypass)

### 6) BLESS/CODEGEN CORRECTNESS: malformed bless still blesses at compile-time, but may not enforce at runtime  
**Script:**

**Why not caught:** CST taint pass treats this as a bless and marks `x` blessed. Lowering/transform only emits `SsaInst::Bless` if it finds a parsed `TestExpr`; otherwise it becomes a regular command, so runtime enforcement can be skipped while taint is “cleared” in the analyzer.  
**Severity:** HIGH

### 7) DD#46 POSITIONAL/TAINT BYPASS: `$@` inside functions leaks the *program* argv (not the call args)  
**Script (compile-clean, but leaks argv at runtime):**
```bash
#!/bin/bash
f() { echo "IN_F:$@"; }
f SAFE
```
Run the compiled binary with args (e.g. `./prog A B`): in Bash this prints `IN_F:SAFE`; with current SSA/codegen model it can print `IN_F:A B` (program argv), because function-call inlining sets `#` and `1..9` but never redefines `@`/`*`, and dynamic `$@`/ArgvIndex paths read from global `sash_argv`.  
**Why not caught:** taint.rs explicitly marks `"@"`/`"*"` clean in function bodies, assuming call-site quarantine, but SSA/codegen don’t actually rebind `$@` to the call args.  
**Severity:** CRITICAL
