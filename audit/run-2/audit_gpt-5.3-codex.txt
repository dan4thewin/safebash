1. **Function/global taint bypass (definition-time snapshot only)**  
   ```bash
   #!/bin/bash
   x="clean"
   leak() { echo "$x"; }
   x=$(getenv SECRET)
   leak
   ```
   **Why uncaught:** `handle_function_def` analyzes function bodies once, then restores state. Later re-taint of globals is not rechecked at call sites; calls with no tainted args pass.  
   **Severity:** **CRITICAL**

2. **Here-string false-clean (`read`)**  
   ```bash
   #!/bin/bash
   x=$(getenv SECRET)
   read y <<< $x
   echo "$y"
   ```
   **Why uncaught:** `handle_read` marks `read` targets clean whenever `<<<`/`<<` exists, without checking redirect content taint; redirect expression is not taint-checked in this path.  
   **Severity:** **CRITICAL**

3. **Heredoc false-clean (`read`)**  
   ```bash
   #!/bin/bash
   x=$(getenv SECRET)
   read y <<EOF
   $x
   EOF
   echo "$y"
   ```
   **Why uncaught:** Same root cause as above; heredoc presence is treated as clean source even when body expands tainted vars.  
   **Severity:** **CRITICAL**

4. **`bless` can bless without a real test (runtime enforcement skipped)**  
   ```bash
   #!/bin/bash
   x=$(getenv SECRET)
   bless x nope
   echo "$x"
   ```
   **Why uncaught:** `handle_bless` blesses as long as a var name exists. In lowering/SSA, if no parsed `TestExpr` is found, it becomes a normal command, not `SsaInst::Bless`; no bless validation path is emitted.  
   **Severity:** **CRITICAL**

5. **Blessing wrong variable / tautology**  
   ```bash
   #!/bin/bash
   x=$(getenv SECRET)
   ok=1
   bless x [[ -n $ok ]]
   echo "$x"
   ```
   **Why uncaught:** No check that bless test actually constrains blessed var. Any truthy clean expression blesses `x`.  
   **Severity:** **HIGH**

6. **Parameter-expansion operand taint bypass**  
   ```bash
   #!/bin/bash
   safe=""
   x=$(getenv SECRET)
   echo "${safe:-$x}"
   ```
   **Why uncaught:** `check_expr_reads`/`expr_is_tainted` for `expansion` checks primary var/subscript but not operator operand trees (like `:-$x`).  
   **Severity:** **HIGH**

7. **Arithmetic-assignment laundering**  
   ```bash
   #!/bin/bash
   x=$(getenv SECRET)
   n=$((x + 0))
   echo "$n"
   ```
   **Why uncaught:** `expr_is_tainted` does not treat `arithmetic_expansion` as tainted when assigning, so `n` becomes clean.  
   **Severity:** **HIGH**

8. **DD#46 compile-time bypass via `shift` then positional read**  
