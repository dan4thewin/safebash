## Contract

[DD135](../decisions/DD135-err-readonly-inputs-nul-and-mkdtemp.md) adopts
zero-argument `$(mkdtemp)`: a direct clean/NUL-free value and a real
operational creation status. It is not an external `mktemp` wrapper or a
stdout capture. Use fixed `/tmp`, a fixed prefix and a generated
restricted-alphabet suffix. No prefix/template operand or `TMPDIR` fallback.

Creation is atomic and exclusive, with owner-only directory access; retry
collisions rather than accepting an existing object. Select the randomness,
suffix, syscall interface and runtime representation when implementing,
using DD129's public-rustix/shared-Linux-shim boundary. This recording
selects none of those mechanisms.

An ordinary `work=$(mkdtemp)` aborts on unhandled creation failure before
assignment. `if work=$(mkdtemp) { ... }` uses DD88's existing untyped
capture-condition consumers. Handled recoverable failure binds empty text
and reports failure; it never exposes the preceding attempt's pathname.
`work=$(- mkdtemp)` retains that failure value while explicitly discarding
the operation's status. No result belongs to assignment itself.

Apply DD130 to the actual error cause and resulting state. Ordinary path/
creation errors are recoverable; heap exhaustion and other fatal faults
cannot become empty results. Keep failures visible under the existing
diagnostic/handling convention, including after collisions and failed use
of `/tmp`.

## Implementation and acceptance

Wire the builtin through canonical recognition, arity/type/result
classification, direct value lowering, native/C runtime calls and artifacts.
It remains the sole producer in its capture (DD111), not an arbitrary bare
statement. An already-discarded status cannot become a condition result.

Record **both** clean provenance and NUL-freedom. A clean value alone still
faces ERR's possible-NUL argv guard. Returning generated bytes directly is
not DD127's kernel-backed capture; unrelated fd reads remain taint sources.
Assigning the result to an already-tainted live binding does not erase its
unresolved taint.

Prove initial-empty/success/failure cleanup state, wrong arity and placement,
status publication, error-before-assignment versus handled empty replacement,
and actual independent byte/taint facts. Trace fault injection to the
intended creation attempt and prove collision handling without depending
on chance. Keep created test directories private and clean up only owned
paths.

The [readonly ERR/proof task](err-readonly-inputs-and-nul-proofs.md) owns
import restrictions. This constructor does not require its new backward
predicate query for a statically NUL-free result. It can land independently
of the full [recoverable-file-failures](recoverable-file-failures.md) inventory,
while coordinating the shared classification and actual ERR failure model.
Update the tour checker's acquisition/cleanup when this builtin is delivered,
not by making today's checker rely on pending syntax.
