# Extract InstCtx setup boilerplate from codegen handlers

`block_dupes` (indexnudge v7) surfaces the largest extraction
candidate in the codebase, all in `sash/src/codegen/`:

| occurrences | shape |
|---|---|
| 23 | handler signature: `builder: &mut FunctionBuilder, module: &mut ObjectModule, ctx: &mut InstCtx,) -> bool {` |
| 21 | signature + first setup line |
| 16 | the four-line setup `let vars = &mut *ctx.vars; let literals = ctx.literals; let externs = ctx.externs; ...` |

23 handlers all open with the same four-line dance to destructure
`InstCtx` into local mutable borrows. The boilerplate predates the
`InstCtx` struct itself (which already exists to bundle these refs)
and reads like the result of mechanical refactoring that didn't go
all the way.

## Approach options

1. **Macro** (`destructure_ctx!(ctx => vars, literals, externs)`).
   Cheapest. Each handler keeps its three local bindings, but
   the four-line ritual collapses to one.
2. **Method on `InstCtx`** returning a tuple.
   `let (vars, literals, externs) = ctx.borrow_parts();`
   Same effect, more discoverable than a macro.
3. **Pass the parts directly.** Change the handler signature so
   the parts arrive split. Touches the dispatcher; biggest blast
   radius but cleanest end state.

(2) is probably the right call — discoverable from the type,
no macro mystery, one-line per handler.

## Investigation (2026-06-08)

DG asked for a sweep of the >= medium-leverage duplication clusters
identified by block_dupes (clusters A through E). The InstCtx cluster
was on the list. Findings:

**Cluster A (pre-DD#53 dead `let _xxx = ctx.field` lines)** was a
sibling signal: 100 lines of pure dead code that suppressed
warnings. Removed in commit `982cf07`. That dropped this task's
duplication count from 26 to 17 active sites.

**Option (2) tested in a minimal repro:**

```rust
impl<'a> InstCtx<'a> {
    fn env(&mut self) -> (&mut HashMap<_, _>, &'a HashMap<_, _>, &'a ExternFuncs) {
        (self.vars, self.literals, self.externs)
    }
}

fn handler(ctx: &mut InstCtx) {
    let (vars, _literals, _externs) = ctx.env();
    vars.insert(...);
    let _z = ctx.other_var;      // E0503: cannot use ctx.other_var
    vars.insert(...);            // because it was mutably borrowed
}
```

The `&mut self` receiver mutably borrows *all* of `*ctx` for the
lifetime of the returned tuple. Any later `ctx.<other_field>` access
fails. The current 3-line destructure works because each
`let X = ctx.field` is a *split borrow* — Rust tracks the borrow at
field granularity, not whole-struct.

Most codegen handlers DO interleave (vars, literals, externs) usage
with access to other ctx fields (exit_status_var, test_result_var,
end_cl_block, etc.). So option (2) is structurally incompatible with
the handler shapes.

**Remaining viable options:**

(a) Rewrite all handler bodies to use `ctx.vars`, `ctx.literals`,
    `ctx.externs` directly — works (already done in emit_exec,
    handle_cd, handle_assign during the cohort wave) but a big
    mechanical change across 17 handlers.

(b) `macro_rules!` to hide the 3 lines behind one call. The
    bindings still exist, just generated by the macro. Trade-off:
    IDE jump-to-definition lands on the macro; hidden parameter
    names become magic.

Neither is a clear win over the status quo. **Deferred** pending a
decision on which path (or whether to keep the destructure as-is).

## Locating callsites

```bash
sqlite3 .indexnudge-rust.db "
  SELECT occurrences, sites FROM block_dupes
  WHERE shingle LIKE '%let vars = &mut *ctx.vars%'
  ORDER BY occurrences DESC LIMIT 5;"
```

## Why now

This is the top duplication hotspot in the codebase by a wide
margin. Doing it shrinks every codegen handler, makes new handler
additions follow a one-line pattern, and demonstrates the
`block_dupes` workflow for future refactors.
