## Likely implementation

1. Add a `mk status` target that runs:
   ```sh
   sqlite3 spec.db "SELECT status, COUNT(*) FROM test_status GROUP BY status"
   ```
   and overwrites a delimited block in `notes/status.md`, e.g. between
   `<!-- BEGIN: spec-status -->` and `<!-- END: spec-status -->`.

2. Add `mk status` to `mk test` so every test run regenerates the
   block. Drift becomes structurally impossible.

3. Hand-edited prose around the block stays untouched.

4. Bonus: do the same for the cargo-test counts in `audit.md` (Brush
   case totals) — same drift pattern, smaller scope.

## Why P4 (depends on D2)

Can't write the script until DG decides the shape. After that, it's a

## Risk

context. Delimited blocks keep the regeneration surgical.
