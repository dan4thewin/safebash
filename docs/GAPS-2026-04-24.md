## Validator / Safety (compile-time rejection rules)

Listed in TODO.md as planned but unimplemented:

- **`alias` rejection rule** (DD#11). Textual substitution; suggest function.
- **`set`/`shopt` table-driven rule** (DD#20). Strip consistent options
  (`set -e`, `shopt -s lastpipe`); reject contradictory ones (`set +e`,
  `shopt -s dotglob`).
- **`PATH=` assignment rejection** (DD#23). PATH is compile-time-only;
  `env PATH=… cmd` is the escape hatch.
- **`bash -c "literal"` rejection** with guidance to remove the wrapper;
  dynamic form continues to fall under SB4001.
- **Taint inheritance through bare function calls** — *superseded by DD#24
  amendment 2 + SSA taint pass work; no inter-procedural inference.*
- **Adversarial review run-2** — overdue per AGENTS.md after DD#40-46 and
  grammar work. The taint bypass surfaced 2026-04-24 is the kind of finding

## Compilation — High Priority

- **Per-command env vars for externals** (`FOO=bar cmd`). This is the
  documented replacement for the rejected `export` (SB5001), so without it
  that rejection has no escape hatch.
- **Compound-command redirects**: `for…done > file`, `while…done | cmd`,
  `if…fi > file`, etc. Codegen currently handles redirects per simple
  command only. (`codegen.rs:4109` — `// TODO: other redirect types`.)
- **Heredoc with `$(cmd)` substitution** — variable expansion in heredoc
  bodies works; cmdsub doesn't (the lowerer skips it). SB5002 catches the
  dangerous case but the safe coerced path isn't built.
- **Compile-time PATH resolution** (DD#23 mode 2): `--resolve` for embedded
  absolute paths, `--sysroot` for cross-compilation.

## Compilation — Normal

- **Runtime arithmetic modulo (`%`)** — only constant-folded form works.
- **Namerefs** (`local -n ref=target`, `declare -n`) — DD#3 says
  compile-time substitution during inlining; not built.
- **Non-constant elidable function calls** (`codegen.rs:2973` — explicit
  `panic!("not yet supported")`).
- **`--emit-source` coercions** for `${var/pat/rep}` → `${var:s/re/str/}`
  and `"${arr[*]}"` → `$(join @arr)` — grammar wired, lowerer doesn't yet
  record these coercions.

## Language Features (designed, not built)

- **`@arr` iteration syntax** (DD#41) — shorthand for `"${arr[@]}"`.
  Declarations work; iteration form does not.
- **`join` builtin** (DD#41) — `join @arr`, `join sep @arr`. Required to
  retire `IFS` joining. Note: per DD#24 amendment 2, `join` is rejected if
  any element of the array is tainted.
- **`getenv` / `argv` builtins** (DD#42) — `$(getenv HOME)`, `$(argv 1)`
  as the explicit boundary into the taint model. SUBSET.md uses these;
  codegen doesn't expose them as first-class builtins yet.
- **`-` error suppression** (DD#21) — `- cmd` as sugar for `cmd || true`,
  plus the per-segment pipeline coercion described in the DD#21 amendment
  (2026-04-23). Coercer needs to insert `-` on non-terminal segments when
  source lacked `pipefail`.
- **`local fn` for mocking** (DD#18 candidate) — lexically scoped function
  shadowing.
- **Honest trace** (`SASH_TRACE=1`, DD#32) — designed, not built. Runtime
  tracing of values.
- **Fixed-point arithmetic** (DD#36) — `dtoi`/`itod` shipped; full
  fixed-point operators not.
- **Arithmetic overflow traps** (DD#25) — partial; runtime traps on integer
  overflow not fully wired.
- **Pike regex shorthand classes** `\d \w \s` in `${var:s/…/…/}` and `=~`.

## Codegen Rough Edges (panics / unimplemented) **[NEW grouping]**

These are landmines users can hit; each should be either a proper
diagnostic or a real implementation:

- `codegen.rs:2465` — `panic!("unimplemented test operator: {}")`
  (binary `[[ ]]`).
- `codegen.rs:2528` — same for unary tests (currently `eprintln!`,
  no exit).
- `codegen.rs:4109` — `// TODO: other redirect types` in the redirect
  dispatcher.
- `emit_janet.rs:271` — `continue` inside loops emitted via fallthrough;
  needs proper `when`/`unless` restructuring for the Janet oracle.
- `transform.rs:478` — `unset -f func` silently ignored. Should likely be
  a diagnostic (function unset isn't supported and `local fn` is the
  planned replacement).
- The `panic!("undefined …")` cluster in codegen (lines 1871, 1897, 1923,
  1974, 3041, 3676, 3724, 3750, 3755, 3778) — these mean an upstream pass
  let something through that codegen assumed couldn't reach it. They
  should each become either a `Diagnostic` in validation/type-check or
  be unreachable by construction.

## Bash-Divergence Bugs Found This Session **[NEW]**

- **Positional-param leak** — `transform.rs:579+` and `:147+`. Inliner
  defines `$1..$N` from call args but leaves `$N+1..$9` reaching from
  caller. Inside `foo arg1`, `$2` reads program argv[2] instead of empty.
  Fix landed; covered by `pos_func_unbound_positional_is_empty`.
- **Taint analyzer doesn't enter function bodies** — `taint.rs`
  `walk_statement` short-circuits on `function_definition`. `getenv`
  inside a function body bypasses the quarantine. Patched at CST layer
  pending SSA replatform per DD#24 amendment 2.
- **`bless` runtime test not enforced** — empirical: a `bless x [[ … ]]`
  whose pattern doesn't match `x` does not abort at runtime. The taint
  rule is enforced at compile time (good) but the runtime validation that
  bless's contract relies on is elided. Independent of the SSA taint
  work; a codegen issue for `bless` lowering.
